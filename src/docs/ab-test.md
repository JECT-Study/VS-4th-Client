A/B 테스트 노출 정책
목적
몰입형 투표 화면 A안과 B안의 성과를 비교 검증하기 위한 정책.
두 시안을 동일한 도메인에서 함께 운영하며, 유입 경로에 따라 노출 시안을 분기

구현 방식
광고 유입 시,  사용자는 동일한 URL Path로 진입하며 최초 접속 시 A안과 B안 중 하나를 5:5 비율로 랜덤 배정하여 노출

일반 유입
 A안과 B안을 5:5 비율로 랜덤 배정
광고 유입
 A안과 B안을 5:5 비율로 랜덤 배정.
사용자 배정 정책
 일반 유입 사용자는 최초 진입 시 한 번만 랜덤 배정을 수행함
 한 번 배정된 시안은 동일 사용자에게 계속 유지되며 이후 재접속하거나 앱을 다시 실행하더라도 동일한 시안을 노출

예외 처리
저장된 배정값을 조회하지 못한 경우에는 기본 시안(A안)을 노출
비 로그인 상태에서 배정된 사용자가 로그인한 경우에는 기존 배정값을 로그인 사용자 정보로 승계

BE 코멘트
  ① A안/B안 화면 두 개 구현 소민님 시안대로 몰입형 투표 화면을 두 벌 만들어야 합니다. URL은 건드리지 않습니다 — 같은 주소에서 UI만 갈아끼우는 구조입니다. ② 응답의 variant 값으로 화면 선택 (랜덤 로직 직접 만들기 x) 몰입형 피드 응답에 필드가 하나 늘었습니다: // GET /api/immersive-votes { "votes": [...], "nextCursor": 20, "hasNext": true, "variant": "A" } // POST /api/immersive-votes/next { "items": [...], "variant": "B" } "A" 또는 "B" 문자열입니다. 이 값만 보고 화면 고르시면 됩니다. 클라이언트에서 Math.random() 같은 걸로 직접 뽑으면 안 됩니다. 그러면 같은 사용자가 새로고침할 때마다 시안이 바뀌어서 "이 사람이 A를 보고 투표했는지 B를 보고 했는지" 알 수 없게 되고, A/B 테스트 데이터가 통째로 못 쓰게 됩니다. 서버가 배정하는 방식이라 새로고침해도 같은 시안이 유지됩니다. 시안 값을 서버로 되돌려 보낼 필요도 없습니다. 지표 수집은 서버가 합니다.
  ③ 요청에 쿠키 포함 필수 (제일 중요) 시안 배정이 anonymous_id 쿠키를 기준으로 이뤄집니다. 요청에 쿠키가 안 실리면 서버가 매번 새 사용자로 인식해서 시안이 계속 바뀌고 데이터가 오염됩니다. // axios axios.get('/api/immersive-votes', { withCredentials: true }) // fetch fetch('/api/immersive-votes', { credentials: 'include' })
  참고로 비회원도 됩니다. 몰입형 API는 로그인 없이 호출 가능하고, 비회원도 시안이 정상 배정됩니다. 광고로 유입된 비로그인 사용자가 주 대상이니 이게 중요합니다.
